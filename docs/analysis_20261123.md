# 五、发现的问题（按严重度排序）

### 🔴 P1 · 融合把 P_UP 压向 50，MC 几乎永不投方向票

因为 `w_w ≥ 0.65` 且「**分歧越大越信 W**」，而 W 的 P_UP 又普遍贴近 50，融合等于对强动量信号做强收缩：

| 指标                                    | 原始 D      | 融合后                      |
| --------------------------------------- | ----------- | --------------------------- |
| mean \|P_UP − 50\|                     | 8.7         | **3.1**（压缩到 36%） |
| 13 个白名单对子中 MC 方向票（阈值 55%） | **8** | **1**                 |

日志完全印证：所有对子 `MC=NEUTRAL`、`BUY=0/3`，三票共识退化成「Strength + XGB」两票。**W 融合实际上把一个有效信号源（D 动量）给中和掉了**。

### 🔴 P2 · 概率仓位路线读的是**原始 D**，不是融合值

[f#L2880](file:///home/ubuntu/projects/ai_training_cnn/fx_trade_bot_v685.py#L2880) 的 `prob_index` 是**独立重新读文件**（[interface.py 每次 read+parse，无缓存](file:///home/ubuntu/projects/fx_monte_carlo/interface.py#L60-L64)），而融合只写进 `mc_cache`。同一笔交易里：

| 消费者                             | 数据源 | 用途                           |
| ---------------------------------- | ------ | ------------------------------ |
| `mc_cache`（融合）               | W+D    | M 分、共识、regime             |
| `prob_index`（**原始 D**） | 仅 D   | conv / risk_cap / 开仓对齐门控 |

具体后果（EUR_USD SELL，base_lot=10000）：

|                              | p_down(aligned) | S→conv      | width→risk_cap | size_scale | 归一化后 units |
| ---------------------------- | --------------- | ------------ | --------------- | ---------- | -------------- |
| 原始 D（**实际生效**） | 64.7%           | 0.294→0.735 | 2.13%→0.94     | 0.735      | **5000** |
| 融合（**未生效**）     | 54.5%           | 0.09→0.25   | 6.61%→0.30     | 0.25       | **2500** |

→ 同一个仓，融合口径会开 **2500**，实际却开了 **5000**（2×）。更极端：`EUR_JPY` 融合口径 p_down=46.4% **低于 50% 门控 → 应直接 SKIP**，但原始 D 的 63.7% 让它通过。
**结论：Profile 2 的「W+D 实验」只改到了共识票和 regime，没改到真正决定仓位/TP 的执行层。**

### 🟠 P3 · 融合记录内部不自洽

`d_blend = dict(d)` 是浅拷贝，只更新了顶层 `p_up/p_down/drift/vol/range_90/regime`。以下字段**仍是 D 独占的旧值**：

- `prob_bands.shape.prob_below/prob_above`（如 64.7%，而顶层已是 45.5%）
- `belief.*`（prior/posterior/verdict/edge 全是 D 的）
- `distribution.quantiles`（TP 目标带 `_band_edge` 读的正是它）

→ 同一记录里「顶层 P_UP=45.5%」与「belief/posterior/先驱=按 D 的 64.7%」并存。宽度门用融合 `range_90`、TP 带却用 D 的 `quantiles`，口径混用。
（TP 因 `TP_MAX_MULT=2.0` 封顶 60p，实际影响被掩盖；但 `belief.verdict` 直接喂给 `_advisory` 健康闸门和 soft 罚乘子，是实质影响。）

### 🟠 P4 · 融合 regime 字符串破坏子串匹配

融合后 `regime` 变成 `"🧬 FUSED | D:MOMENTUM W:NEUTRAL | w_w=77%"`，而 [_regime_mult](file:///home/ubuntu/projects/ai_training_cnn/utils/prob_zone_sizing.py#L204-L217) 靠 `"MOMENTUM" in text` 判定。实测：

| 融合串                   | regime_mult             |
| ------------------------ | ----------------------- |
| `D:MOMENTUM W:NEUTRAL` | **1.0**（不降仓） |
| `D:RANGE W:NEUTRAL`    | 0.25                    |
| `D:NEUTRAL W:NEUTRAL`  | 0.25                    |

→ 只要 D **或** W 任一说 MOMENTUM，就跳过 regime 降仓；D 和 W 的语义被混成一锅。这是把单周期字符串匹配器直接喂给复合串的副作用。

# 六、建议

1. **P2 优先**：让 `prob_index` 复用 `mc_cache`（融合后），或明确「实验只作用于共识」并在文档/日志写死——二者必须二选一，现在处于含糊的中间态，最危险。
2. **P1**：重新审视 `w_w = 0.65 + dev×0.6`。当前「越分歧越信 W」在 W≈50 时会系统性抹掉 D 的动量信号；建议改为**分歧越大越保守**（降低总权重/收窄到中性），或设 `w_w` 上限远低于 0.85。
3. **P3**：融合时同步重算 `prob_bands` / `belief` / `distribution.quantiles`，或把 `blend_source` 之外的派生块整体标记为不可信，避免半融合记录。
4. **P4**：给 `_regime_mult` 传入独立的、单周期的 regime 字段（或让融合串另存 `regime_D` / `regime_W` 两份原始标签）。
5. **W 数据质量**：对 `lookback=260` 长窗做尾部/异常年剔除或 winsorize，否则 USDCAD ±10%、CADJPY ±8% 的 4 周区间会持续污染任何吃 W 区间的逻辑。
6. 补 `metadata.total_pairs` 回填（35→28），并补 `pandas_ta` 到运行环境。

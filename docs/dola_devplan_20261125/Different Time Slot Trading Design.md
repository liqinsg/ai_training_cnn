## 一、设计原则

> **总纲定位：时段控入场 + 策略互校验 + 规则不猜谜 + 渐进可回测**

| 原则                                | 说明                                                                         |
| ----------------------------------- | ---------------------------------------------------------------------------- |
| 🕐 **时段优先**               | 先判断"该不该出手"，再算"出什么手"。时段门控是第一道、也是最严的关口         |
| 🤝 **协同而非并行**           | 4个Profile不是独立4条线，而是1个委员会：观点加权投票、互相抑制、动态置信校正 |
| 🛡️ **休眠≠断开**           | 非专属时段的Profile不生成信号，但参与全局评估——"不投票但可以否决/提醒"     |
| ⏱️ **时间驱动、事件校验**   | 时段边界是时间驱动；跨时段核验、方向反转、异常跳空是事件驱动                 |
| 🔧 **配置驱动、硬编码最小化** | 时段规则、Profile权限、投票权重全部可配置，改策略不用改核心流程              |
| 📊 **可观测、可回测**         | 所有决策路径输出审计日志：谁投了票、为什么通过/否决、置信如何被修正          |

## 三、核心模块职责

### 3.1 时段门控器 (`TimeGate`) — 第一道关口

> "什么时候允许、什么时候休息、夏令时怎么算"

| 职责            | 详细说明                                            |
| --------------- | --------------------------------------------------- |
| ✅ 时段判定     | 根据当前时间+夏令时规则 → 返回当前时段类型         |
| ✅ 权限掩码     | 返回该时段允许运行的Profile列表、置信偏移、仓位上限 |
| ✅ 停战计时     | 14:30后禁止P3新开；00:00后冻结所有新开逻辑          |
| ✅ 时段边界事件 | 14:50欧洲开盘预核验、08:55隔夜清理触发点            |
| ✅ 夏令时偏移   | 根据生效日历自动修正时段起止时间，不硬编码          |
| ✅ 假日降级     | 检测市场半休/闭市 → 自动切换到对应降级模板         |

**输出结构示例：**

```json
{
  "session_id": "asian_morning",
  "session_name": "亚洲早盘",
  "allowed_profiles": ["P3"],
  "confidence_bias": 10.0,
  "lot_multiplier": 0.25,
  "max_new_per_pair": 2,
  "is_trading_open": true
}
```

### 3.2 Profile投票器 (`StrategyVoter`) — 协同核心

> "4个Profile怎么互相影响、一票否决、加权放大"

| 职责            | 详细说明                                             |
| --------------- | ---------------------------------------------------- |
| ✅ 信号收集     | 收集所有活跃Profile对同一交易对的方向+置信           |
| ✅ 共识分级     | 高度共识/基本一致/严重分歧/单人孤证 → 分级判定      |
| ✅ 动态置信修正 | 同向叠加+5/反向抵消-10 → 输出最终有效置信           |
| ✅ 额度分配系数 | 共识等级→仓位乘数：1.0 / 0.5 / 0.0                  |
| ✅ 休眠权重规则 | 非活跃时段Profile：不生成主信号，但可投反对票/中性票 |
| ✅ 审计输出     | 完整记录：谁投了什么票、原始置信→修正后置信、原因码 |

**投票数据结构：**

```json
{
  "pair": "AUD_USD",
  "candidates": [
    {"profile": "P3", "direction": "SELL", "confidence": 62.3, "active": true},
    {"profile": "P2", "direction": "NEUTRAL", "confidence": null, "active": false}
  ],
  "consensus_level": "single_verified",
  "final_direction": "SELL",
  "adjusted_confidence": 62.3,
  "lot_factor": 0.25,
  "decision": "ALLOW",
  "reason": "P3_SOLO_ASIAN_SESSION"
}
```

### 3.3 跨时段核验器 (`SessionAudit`) — 防暴击核心

> "亚洲持仓到欧洲开盘，要不要先撤再看"

| 职责            | 详细说明                                           |
| --------------- | -------------------------------------------------- |
| ✅ 持仓继承校验 | 亚洲盘P3持仓 → 欧洲开盘前用P2/P4信号重新评估      |
| ✅ 方向冲突判定 | 新主流方向 vs 持仓方向 → 强度差阈值触发预警       |
| ✅ 主动离场建议 | 冲突时：保本/小亏离场，不硬等SL被击穿              |
| ✅ 持仓时长限制 | 亚洲入场单→15:00前必须复核/离场，不无限跨时段     |
| ✅ 隔夜清理     | 08:55扫描：非预期隔夜单、低置信持仓→预警/平仓建议 |

## 五、Profile协同模型

### 5.1 角色与权重定义

| Profile      | 时段主场         | 基础权重          | 否决权                       | 休眠行为                        |
| ------------ | ---------------- | ----------------- | ---------------------------- | ------------------------------- |
| **P1** | 欧美重叠 20–00  | 0.35              | 置信≥60可否决反向低置信信号 | 不生成信号，权重→0，可投反对票 |
| **P2** | 欧洲+欧美 15–00 | 0.30              | 始终有否决权（基准策略）     | 不生成信号，权重→0，可投反对票 |
| **P4** | 欧洲+欧美 15–00 | 0.25              | 结构突破反向时可否决         | 不生成信号，权重→0，可投反对票 |
| **P3** | 亚洲盘 09–15    | 1.00 ⚠️临时独占 | 亚洲时段：无其他否决权       | 欧洲后：权重→0.1，仅风控否决   |

> ⚠️ **亚洲时段特例**：09:00–15:00，P3权重临时=1.0，其余Profile不参与投票也不行使否决权——避免"质量低的时段还要等共识"导致信号全部错过

### 5.2 共识分级规则（标准时段）

| 等级        | 条件                              | 置信修正             | 仓位系数 | 决策                   |
| ----------- | --------------------------------- | -------------------- | -------- | ---------------------- |
| 🟢 高度共识 | ≥3同向且≥门槛                   | 基础+5×(N-2)        | ×1.0    | ✅ 放行                |
| 🟡 基本一致 | 2同向且≥门槛，其余中性           | 基础+0               | ×0.5    | ⚠️ 减半放行          |
| 🔴 严重分歧 | ≥2双向互斥且≥门槛               | 主方向-10，次方向-10 | ×0.0    | ❌ 禁止                |
| ⚪ 单人孤证 | 仅1个Profile达标，其余休眠/不达标 | 基础-5               | ×0.25   | ⚠️ 亚洲放行/其余观望 |

## 六、配置体系结构

### 6.1 文件清单

```
config/
├── config_profile.json          # 原有Profile基础参数（保留）
├── config_session.json          # ✨ 新增：时段定义+权限规则
├── config_voting.json           # ✨ 新增：投票权重+共识阈值
├── config_calendar.json         # ✨ 新增：夏令时起止+主要假日
└── config_dynamic_override.json # 可选：临时紧急覆盖（如突发新闻日）
```

### 6.2 配置设计原则

- **原有Profile配置不动**：向后兼容，不破坏现有回测/实盘基线
- **新规则全部外置JSON**：调整时段/权重/假日不用改代码
- **层级优先级**：动态覆盖 > 当日假日规则 > 夏令时修正 > 标准时段定义
- **版本化+注释**：每个配置文件自带`schema_version`和`description`字段

## 七、实施阶段规划

> **核心原则：接口先预留、逻辑分阶段、每阶段可独立回测验证、不一步大改**

| 阶段              | 模块                    | 目标                                                   | 验证输出                           |
| ----------------- | ----------------------- | ------------------------------------------------------ | ---------------------------------- |
| **Phase 0** | TimeGate 时段门控       | 正确识别时段+夏令时+假日；00–09禁止新开               | 日志：时段判定正确；凌晨无新单日志 |
| **Phase 1** | P3亚洲独立运行          | 09–15仅P3生成信号；参数自动切换（置信+10/仓位×0.25） | 日志：亚洲仅P3决策；参数生效正确   |
| **Phase 2** | SessionAudit 跨时段核验 | 14:50自动复核亚洲持仓；方向冲突→主动离场建议          | 日志：核验触发；冲突时输出平仓建议 |
| **Phase 3** | StrategyVoter 基础投票  | 标准时段2+Profile信号→共识分级/置信修正/仓位缩放      | 日志：完整投票轨迹；决策与规则一致 |
| **Phase 4** | 否决权+动态权重         | 休眠Profile反对票生效；P3权重时段自动切换              | 日志：否决触发时信号被抑制         |
| **Phase 5** | 绩效反馈回路            | 按共识等级/时段分别统计胜率→权重自适应微调            | 报告：等级别盈亏对比；权重漂移追踪 |

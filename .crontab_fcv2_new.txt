# ─── MC data updates — 每 6 小时一组，严格按伦敦时间 (00/06/12/18 London) ───────
# 2026-11-17: 原为 `0 8 * * *`（=SG 08:00）。SG 全年 UTC+8，而伦敦有夏令时，
#   故 08:00 只在冬令时等于伦敦 00:00，BST 期间会漂成伦敦 01:00 —— 即原调度
#   并未真正踩伦敦 0 点。本机 cron (Debian 3.0) 不支持按时区调度（man crontab:
#   TZ 只影响命令环境，不影响触发时刻），故改为「每小时触发 + 命令内判时」。
#
# 触发条件 = 伦敦小时 ∈ {00,06,12,18}  或  UTC 小时 = 00（夏令时桥接）。
#   * 冬令时：伦敦 == UTC，UTC 00 与伦敦 00 是同一时刻 → 仍 4 次/天，不重复触发。
#   * 夏令时：伦敦 00:00 = UTC 前一天 23:00，仅靠伦敦基准会留下当日无快照的空窗；
#     补一次 UTC 00:00 桥接 → 5 次/天，当日快照零空窗。
# 说明：MC 生产端与 bot 消费端的「日」标签都用 UTC（文件名 mc_D_all_pairs_<UTC日>_<UTC HHMM>.json），
#   与恒定 UTC+8 的 SG 不同，因此这里必须按 London ∪ UTC 双基准判断。
# 注：run_fx_mc.sh 内部用 `date +%u` 判断周一以生成周线(W)，TZ=Europe/London 令其按伦敦周几判断；
#   伦敦周一当天每次触发都会重跑 W（幂等覆盖同名文件，仅多耗 CPU）。
0 * * * * LH=$(env TZ=Europe/London date +\%H); UH=$(date -u +\%H); if [ "$LH" = 00 ] || [ "$LH" = 06 ] || [ "$LH" = 12 ] || [ "$LH" = 18 ] || [ "$UH" = 00 ]; then TZ=Europe/London $HOME/projects/fx_monte_carlo/run_fx_mc.sh >> $HOME/projects/fx_monte_carlo/mc_cron.log 2>&1; fi
